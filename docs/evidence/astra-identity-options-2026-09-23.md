# Astra and local options for All-22 player identity

Checked 2026-09-23. This is a source review and an experiment proposal. No footage was sent to a service, no API was enabled, and the examples below are **not** results on this repository's All-22 clip. See the existing [cross-shot automation research](cross-shot-identity-automation-research-2026-09-22.md) for the local pipeline and evaluation gates.

## What the Roboflow example actually shows

The model is **OpenAI GPT-6 Astra** (`gpt-6-astra`), not a Roboflow-hosted tracker. In [Roboflow's September 18 vision report](https://blog.roboflow.com/gpt-6-astra-vision/), the authors supplied basketball frames sampled at **one frame per second** and asked Astra for boxes, consistent player IDs, teams, and jersey numbers. They report that IDs persisted across plays and substitutions in the illustrated clips. They give no quantitative cross-shot identity score or NFL All-22 validation. Their recommended combination uses RF-DETR and BoT-SORT for frequent local updates, with Astra for sparse interpretation. This is a useful optional ranker or annotation proposer, not evidence that it can replace source-frame tracking, play alignment, or field calibration. [Roboflow's football tutorial](https://blog.roboflow.com/american-football-player-tracker/) uses RF-DETR and ByteTrack for consecutive-frame track IDs; it likewise does not establish cross-view identity or field-space reconstruction.

Astra [accepts images but has no native video input](https://developers.openai.com/api/docs/models/gpt-6-astra). Roboflow's [video demonstration](https://blog.roboflow.com/gpt6-astra-video-understanding/) sent timestamped still frames and requested structured event output. For this project, frames from the two shots would need explicit original source frame, PTS, shot ID, and aligned play time; a model's returned ID would remain a **proposal**. A one-FPS sample can omit the small pose, contact, jersey, and interaction details that distinguish adjacent football players, and Roboflow did not measure that failure mode on All-22 footage. The API also means sending sampled images outside the local environment.

## Local-first path and optional comparison

| Route | Role in this project | Cost and evidence boundary |
| --- | --- | --- |
| Existing local detector/tracker, geometry, and cues | Keep RF-DETR/BoT-SORT or other explicitly selected local backends for every-frame boxes and shot-local tracks. Use source-specific timing and calibration, conservative assignment, local jersey/appearance proposals, and CVAT review. | No per-image API charge; hardware, model acquisition, runtime, and review labor remain. The repository has the interfaces, but All-22 identity accuracy must be measured here. [RF-DETR's open core models](https://github.com/roboflow/rf-detr) are Apache-2.0; Plus model licensing differs. [CVAT Community](https://docs.cvat.ai/docs/products/community/) is free and self-hosted. |
| Local football-specific model improvement | Collect reviewed, high-quality crops and hard crossing examples; fine-tune detection/jersey cues, then compare with the same detection cache and sealed play split. A [Roboflow soccer prototype](https://blog.roboflow.com/make-automatic-highlight-reels-from-soccer-games/) illustrates local jersey voting, periodic rechecks, and splitting a track after repeated disagreement. | Local compute and labeling effort. Its soccer prototype is not an NFL accuracy claim. Existing [football tracking research](cross-shot-identity-automation-research-2026-09-22.md) notes a published football ablation where detector tuning mattered more than ReID tuning; reproduce the comparison on this footage before prioritizing learned ReID. |
| Sparse Astra review aid, **off by default** | On a small, consented, previously reviewed play set, ask for candidate same-player pairs or readable jersey numbers from source-addressed stills. Compare blinded decisions with local geometry/jersey candidates; preserve the model response and abstentions separately from review truth. | External API charge and image transfer. No deployment or label promotion from a demonstration. [Roboflow's report](https://blog.roboflow.com/gpt-6-astra-vision/) provides the design precedent, not a guaranteed transfer result. |

**Suggested test:** choose two or three genuine same-play sideline/end-zone pairs with independently reviewed source-frame tracks, anchors, shot-specific calibration, and cross-shot identity. Freeze the local candidate list. Compare (1) local geometry/team, (2) local geometry/team plus local jersey/appearance, and (3) the same candidates reranked by sparse Astra frames. Count correct, false, missed, and abstained links; component contamination; calibration/timing validity; human minutes; and API tokens/cost. Do not allow an Astra answer to alter reference labels. A single false merge blocks promotion under the [evaluation plan](../evaluation-plan.md). This experiment needs reviewed pairs; the two shots in the short sample alone do not provide those labels or guaranteed time overlap.

## Budget, if an API comparison is later authorized

The [OpenAI API price page](https://developers.openai.com/api/docs/models/gpt-6-astra) lists Standard short-context GPT-6 Astra at **$10 per million input tokens and $50 per million output tokens**; Batch/Flex are 50% of Standard. Image size, crop count, output/reasoning tokens, and context length change the actual bill. [Roboflow observed](https://blog.roboflow.com/gpt-6-astra-vision/) roughly **$0.02–$0.08 per sampled frame** in its vision experiments, not a football-specific tariff. Its [100-frame, 768×432 tennis event example](https://blog.roboflow.com/gpt6-astra-video-understanding/) cost about **$1** and took two to three minutes, but the output task differs from identifying 22 players across two views.

For the repository's 1,424-frame, ~23.8-second sample, Roboflow's observed per-frame range would imply roughly **$0.48–$1.92 at 1 FPS (~24 frames)** or **$2.40–$9.60 at 5 FPS (~120 frames)**. These are arithmetic planning ranges, **not quotes or measured costs** for this video. A full-frame Astra pass at native ~60 FPS would be about **$28–$114** at the same assumed rate and would still lack native tracker/calibration outputs. The local route incurs no Astra API charge. Roboflow's [current platform pricing page](https://roboflow.com/pricing) separately lists a free Public tier and a private-data Core tier at **$79/month billed annually or $99 month to month**. That subscription is not required to run the repository's local components or to call the OpenAI API directly.
